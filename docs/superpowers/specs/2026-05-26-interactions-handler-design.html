Slack Interactivity Handler

Issue #27  ·  Branch: v2  ·  P1 Small  ·  2026-05-26

Goal

Add a POST /slack/interactions endpoint that receives Slack interactive component payloads (button clicks, modal submissions), verifies the request signature, dispatches by interaction type and action ID, and persists config changes to SQLite. The first concrete action: an "Edit" button in /calendar config that opens a schedule-editing modal.

Locked Decisions

Load-bearing choices — do not revisit during implementation.
DecisionRationale
Payload parsing via URLSearchParams Slack sends interactions as application/x-www-form-urlencoded with a single payload field containing JSON. readAndVerify already reads the raw body; caller does JSON.parse(new URLSearchParams(rawBody).get('payload')).
new WebClient(botToken) per request Multi-tenant: each workspace has its own encrypted bot_token in SQLite. No global Slack client. WebClient is instantiated with the workspace token fetched from DB per request.
_setApiClientForTest(fn) injection Same pattern as _setRunnerForTest in commands.js. Keeps @slack/web-api out of test assertions while still verifying correct arguments.
Schedule editing only (not calendar assignment) Stays within the Small size label. Calendar assignment (multi-select from available calendars) is a separate future concern.
onReschedule callback from server.js Keeps interactions.js decoupled from scheduler-registry.js. Mirrors onInstall in oauth.js and onUninstall in events.js.
Validate schedule via scheduleStringToCron Reuses existing validation logic. Returns Slack inline errors (response_action: 'errors') rather than crashing.
Empty schedule input → null in DB null disables the schedule. Consistent with how the scheduler treats missing schedules (no cron job created).

Request Flow

Step-by-step

1
POST /slack/interactions arrives as application/x-www-form-urlencoded with a single field payload containing JSON.
2
readAndVerify(req, secret) reads the raw body and checks HMAC-SHA256 signature + timestamp. Throws {statusCode:403} on failure.
3
Parse: const payload = JSON.parse(new URLSearchParams(rawBody).get('payload')). Return 400 if field missing or JSON malformed.
4
getWorkspace(db, payload.team.id). If null (workspace uninstalled), ack 200 empty and return.
5
Dispatch by payload.type:
  • block_actions → loop payload.actions, dispatch each by action.action_id
  • view_submission → dispatch by payload.view.callback_id
  • view_closed / anything else → 200 empty ack

Modal Design (Block Kit)

The modal is opened by views.open in response to a config_edit_channel button click. It carries schedule state in private_metadata so the submit handler can identify the target channel without Slack session state.

View object

{
  type: 'modal',
  callback_id: 'config_edit_channel',
  private_metadata: JSON.stringify({ workspaceId: 'T...', channelId: 'C...' }),
  title: { type: 'plain_text', text: 'Edit Channel Schedule' },
  submit: { type: 'plain_text', text: 'Save' },
  close:  { type: 'plain_text', text: 'Cancel' },
  blocks: [
    {
      type: 'section',
      text: { type: 'mrkdwn', text: '*#channel-name*' }
    },
    {
      type: 'input',
      block_id: 'digest_schedule_block',
      optional: true,
      label: { type: 'plain_text', text: 'Weekly digest schedule' },
      hint:  { type: 'plain_text', text: 'e.g. "sunday 18:00" or "monday 09:00" — leave blank to disable' },
      element: {
        type: 'plain_text_input',
        action_id: 'digest_schedule_input',
        initial_value: channel.digest_schedule || ''   // pre-filled
      }
    },
    {
      type: 'input',
      block_id: 'daily_schedule_block',
      optional: true,
      label: { type: 'plain_text', text: 'Daily digest schedule' },
      hint:  { type: 'plain_text', text: 'e.g. "weekdays 09:00" — leave blank to disable' },
      element: {
        type: 'plain_text_input',
        action_id: 'daily_schedule_input',
        initial_value: channel.daily_digest_schedule || ''  // pre-filled
      }
    }
  ]
}
Pre-fill requirement: handleConfigEditAction must load the channel row from DB (SELECT digest_schedule, daily_digest_schedule, name FROM channels WHERE workspace_id = ? AND channel_id = ?) to populate initial_value and the channel name in the section header. If the channel row is missing, open the modal with empty initial values.

Submit handler: extracting values

const values = payload.view.state.values;
const digestSchedule  = values.digest_schedule_block?.digest_schedule_input?.value?.trim() || '';
const dailySchedule   = values.daily_schedule_block?.daily_schedule_input?.value?.trim()  || '';

Validation response (invalid input)

// Return as 200 JSON — Slack renders errors inline in the modal
{
  response_action: 'errors',
  errors: {
    digest_schedule_block: 'Invalid schedule format. Use e.g. "sunday 18:00" or leave blank to disable.'
  }
}

Validate each non-empty field independently. If both are invalid, include both block IDs in the errors object.

DB Change — src/db.js

New function: updateChannelSchedule

/**
 * Update digest schedules for a channel.
 * @param {import('better-sqlite3').Database} db
 * @param {string} workspaceId
 * @param {string} channelId
 * @param {string|null} digestSchedule - weekly schedule, or null to disable
 * @param {string|null} dailySchedule  - daily schedule, or null to disable
 */
function updateChannelSchedule(db, workspaceId, channelId, digestSchedule, dailySchedule) {
  db.prepare(`
    UPDATE channels
    SET digest_schedule = ?, daily_digest_schedule = ?
    WHERE workspace_id = ? AND channel_id = ?
  `).run(digestSchedule || null, dailySchedule || null, workspaceId, channelId);
}

Empty string input is coerced to null (disabled). The UPDATE is a no-op if the (workspaceId, channelId) row does not exist — this cannot happen in practice since the Edit button only appears for channels already in the DB.

Add updateChannelSchedule to module.exports.

Route order matters. handleInteractions checks for POST /slack/interactions and returns false otherwise, so inserting it after handleSlashCommand (which checks POST /slack/commands) is safe. The 404 branch remains last.

Error Handling

ScenarioResponseNotes
Bad/missing HMAC signature 403 empty Thrown by readAndVerify, caught in handler.
Stale timestamp (>300 s) 403 empty Thrown by readAndVerify.
Non-POST or path ≠ /slack/interactions return false Not our route — let server.js continue.
payload field missing or JSON malformed 400 empty Slack shouldn't send this, but defend anyway.
Workspace not in DB 200 empty ack Workspace was uninstalled. Ignore silently.
Invalid schedule string on submit 200 + {response_action:'errors', errors:{...}} Slack renders the error inline in the modal. User corrects and resubmits.
views.open API failure 200 empty ack Log [interactions] views.open failed: msg. Best effort — we already showed the button.
DB update failure 200 empty ack Log [interactions] DB update failed: msg. Modal closes; user sees no error (acceptable for now).
Unknown action_id or callback_id 200 empty ack Future-proofing — ignore unknown interactions gracefully.
view_closed type 200 empty ack User dismissed the modal. No action needed.

Test helper: building a valid signed payload 
const crypto = require('node:crypto');

function makeInteractionsRequest(payloadObj, secret = 'test-secret', tsOffset = 0) {
  const ts = Math.floor(Date.now() / 1000) + tsOffset;
  const payloadJson = JSON.stringify(payloadObj);
  const body = new URLSearchParams({ payload: payloadJson }).toString();
  const sigBase = `v0:${ts}:${body}`;
  const sig = 'v0=' + crypto.createHmac('sha256', secret).update(sigBase).digest('hex');
  return {
    method: 'POST',
    url: '/slack/interactions',
    headers: {
      'x-slack-request-timestamp': String(ts),
      'x-slack-signature': sig,
      'content-type': 'application/x-www-form-urlencoded'
    },
    body
  };
}
