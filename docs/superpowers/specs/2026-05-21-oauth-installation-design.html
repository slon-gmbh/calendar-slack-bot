Slack OAuth Installation Flow

Issue #46  ·  Branch: v2  ·  Sprint 3 (May 18–31, 2026)  ·  P0 M

Any Slack workspace admin visits the bot's install URL and clicks "Add to Slack". The OAuth v2 flow exchanges the authorization code for a bot token, which is encrypted and stored in the workspace database. Blocked by: #44 (multi-tenant schema), #45 (credential encryption).

Architecture

The OAuth flow lives entirely in src/oauth.js. server.js calls validateSlackEnvVars() at startup and delegates matching HTTP requests to handleOAuthRequest(db, req, res). The cron scheduler in server.js is unchanged.

Routes

GET /slack/install

  1. Generate a CSRF state token: crypto.randomBytes(16).toString('hex')
  2. Store in PENDING_STATES map with expiry = Date.now() + 10 * 60 * 1000
  3. Redirect 302 to Slack's authorize URL (see Scopes section)

GET /slack/oauth/callback

  1. Parse code and state from the query string
  2. Validate state: missing → 400; not in map → 400; expired → 400. Delete from map regardless.
  3. Call WebClient.oauth.v2.access({ client_id, client_secret, code })
  4. On Slack error: respond 400 with inline HTML error page
  5. On success: call upsertWorkspaceFromOAuth(db, { teamId, teamName, botToken, installedBy })
  6. Redirect 302 to /slack/install/success

GET /slack/install/success

Responds with a minimal inline HTML "Installation complete" page. Served by oauth.js — no template files.

CSRF State

Design choice: The PENDING_STATES map lives at module scope in oauth.js. States are consumed immediately on use (success or failure) and lazily purged: each time a new state is added, stale entries are swept. TTL is 10 minutes. A second request with the same state returns 400 even if not expired — state is single-use.

Requested Bot Token Scopes

chat:write canvases:write im:write commands

chat:write and canvases:write are used immediately (digest posting, canvas updates). im:write is needed for the onboarding DM in #48. commands is needed for slash commands in #26. Requesting all upfront avoids a re-authorization prompt when those issues ship.

Authorize URL structure

https://slack.com/oauth/v2/authorize
  ?client_id={SLACK_CLIENT_ID}
  &scope=chat%3Awrite%20canvases%3Awrite%20im%3Awrite%20commands
  &redirect_uri=https%3A%2F%2F{SLACK_REDIRECT_HOST}%2Fslack%2Foauth%2Fcallback
  &state={state}

db.js Changes

upsertWorkspaceFromOAuth(db, opts)

Inserts a new workspace row or updates an existing one. Always updates bot_token, installed_by, installed_at, and resets active to 1 (re-activates deactivated workspaces).

function upsertWorkspaceFromOAuth(db, { teamId, teamName, botToken, installedBy }) {
  db.prepare(`
    INSERT INTO workspaces (team_id, team_name, bot_token, installed_by, installed_at, active)
    VALUES (?, ?, ?, ?, ?, 1)
    ON CONFLICT(team_id) DO UPDATE SET
      team_name    = excluded.team_name,
      bot_token    = excluded.bot_token,
      installed_by = excluded.installed_by,
      installed_at = excluded.installed_at,
      active       = 1
  `).run(teamId, teamName, encrypt(botToken), installedBy, new Date().toISOString());
}
Contrast with upsertWorkspace(): The config-file seeding function intentionally does not update bot_token on conflict, because the config file may not carry the live token. These two functions have different invariants and must remain separate — no flags, no overloads.

Fields locale, timezone, error_channel, nextcloud_url are not set here — they are populated during workspace onboarding (#48).

listActiveWorkspaces(db)

Returns all active workspaces as an array of plain objects, with bot_token decrypted. Used by the per-workspace cron scheduler in #47.

function listActiveWorkspaces(db) {
  const rows = db.prepare('SELECT * FROM workspaces WHERE active = 1').all();
  return rows.map(row => {
    if (row.bot_token) row.bot_token = decrypt(row.bot_token);
    return row;
  });
}

Alternatives considered

Option A: Inline routes in server.js — Rejected. server.js will accumulate routes in #26 and #27; inlining OAuth would make the file hard to navigate and impossible to test in isolation.

Option C: @slack/oauth package — Rejected. Adds a dependency for 2 route handlers. Slack's official package handles token rotation and installation stores that we don't need (bot_token updates are handled by upsertWorkspaceFromOAuth).

Redis/DB for CSRF state — Rejected. Unnecessary complexity. Fly.io runs a single persistent instance; in-memory state is recoverable within the 10-minute TTL window. If the instance restarts, the admin simply clicks "Add to Slack" again.
